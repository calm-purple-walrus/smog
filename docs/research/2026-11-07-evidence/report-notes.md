# Extra verified notes for the Geiger report

These notes come from reading primary sources directly on 2026-11-07. They are verified facts unless marked as inference.

## desloppify (peteromallet/desloppify)

Read at `main`, commit 3a7735d (2026-05-13, the v1.0 release). PyPI shows 20 releases, from 0.7.0 (2026-02-22) to 1.0 (2026-05-13).

- What it is ([README](https://github.com/peteromallet/desloppify/blob/main/README.md)): "Desloppify gives your AI coding agent the tools to identify, understand, and systematically improve codebase quality." The agent runs `scan`, then a fix loop (`next` → fix → `resolve`). The README calls the score a "north-star" for the agent and says "A score above 98 should correlate with a codebase a seasoned engineer would call beautiful." The README presents no validation data for that sentence.
- Locality ([README](https://github.com/peteromallet/desloppify/blob/main/README.md)): "True incremental or diff-only scanning is not the supported model yet; compare full-codebase results across runs or enforce a project-level threshold."
- Score formula ([docs/scoring.md](https://github.com/peteromallet/desloppify/blob/main/docs/scoring.md)): 0-100 health score. A mechanical pool (automated detectors) weighs 25% and a subjective pool (LLM review of dimensions such as elegance, contracts, type safety, design coherence) weighs 75%. Mechanical dimension score = ((potential - weighted_failures) / potential) * 100. Issue weights by detection confidence: high 1.0, medium 0.7, low 0.3. File-based detectors cap failures per file (1-2 issues count up to 1.0 failure units, 3-5 up to 1.5, 6+ up to 2.0). "Dimensions with fewer than 200 checks get their weight reduced proportionally." Test, config, generated and vendor zones are excluded from scoring. Two variants: lenient, and strict, where `wontfix` issues still count as failures. The doc states: "Scores from different codebases are not directly comparable."
- Anti-gaming ([dev/DEVELOPMENT_PHILOSOPHY.md](https://github.com/peteromallet/desloppify/blob/main/dev/DEVELOPMENT_PHILOSOPHY.md)): "Attestation requirements on resolution — agents have to describe what they actually did"; "Wontfix still counts against strict score"; "Subjective assessments are cross-checked — if scores land suspiciously close to targets, they get flagged or reset". In code, `SUBJECTIVE_TARGET_MATCH_TOLERANCE = 0.05` (`desloppify/engine/_scoring/policy/core.py`).
- Rust plugin ([desloppify/languages/rust/README.md](https://github.com/peteromallet/desloppify/blob/main/desloppify/languages/rust/README.md)): runs `cargo clippy`, `cargo check` and `cargo rustdoc` with JSON output, plus Rust detectors for import hygiene, feature hygiene, API conventions, error boundaries, future-proofing, thread safety, async locking, drop safety, unsafe APIs, and smells such as undocumented unsafe and `#[allow]` attributes. Its module graph "is intentionally best-effort. It does not use `cargo metadata`, rust-analyzer, or compiler internals." Its Rust test coverage "uses heuristics rather than compiler instrumentation."
- Layer rules: the `layer_violation` detector is implemented only in the Python plugin (`desloppify/languages/python/`); the Rust plugin has none.
- Custom rules: project-local plugins are Python files in `.desloppify/plugins/*.py`, loaded only when `trust_plugins` is set in `.desloppify/config.json` or `DESLOPPIFY_TRUST_PLUGINS=1` (`desloppify/base/config/schema.py`, `desloppify/languages/_framework/registry/discovery.py`). They register language modules. No declarative way to add a rule to the built-in Rust plugin was found.
- License: `main` uses the Open Source Native License (OSNL) 0.2: free internal use; paid tiers ($1,000-$10,000/month) apply only to companies that are not open source, have $1M+ funding or revenue, and redistribute the program in a product or service. An unmerged branch `chore/apache-2-license-20261027` (commit abcb31d, 2026-10-27) switches the license to Apache 2.0. `main` has had no commits since 2026-05-13.
- Inference: desloppify's anti-gaming devices (strict vs lenient, confidence weights, per-file caps, sample dampening, flagging LLM scores near the target) are reusable ideas for Geiger. Its 75% LLM-judged pool makes run-to-run noise likely larger than a 0.2-point budget; this was not measured.
